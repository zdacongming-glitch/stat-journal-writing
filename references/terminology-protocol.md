# 核心术语核验

在新术语首次引入或定义前执行。相同概念在同一任务中核验一次，之后复用；方向档案有可信来源且定义未变时，不重新搜索常见名称。

## 核验顺序

1. 明确当前对象及定义，包括模型、条件、目标量和所声称性质。
2. 查本方向 `terms.json`、作者给定的原始论文和最接近研究。
3. 缺来源、有歧义、新造名称或与已知定义不符时，强制检索原始定义及代表性用法。目标期刊用于写法适配，术语来源可以跨期刊。
4. 逐项比较定义；等价则使用惯用名称。相关但不等价时保留区别，必要时说明继承或扩展关系。
5. 确定一个首选名称并全文一致使用，保留该领域正常缩写与大小写。不为词汇变化轮换近义术语。

名称频率不能替代定义比较。例如，“有选择一致性”“有 oracle 性质”和“能进行有效的选择后推断”承载不同主张。`robust`、`efficient`、`optimal` 须明确性质，不用更流行的名称扩大现有结论。

没有完全对应的惯用名称时，优先直接描述对象及关系；确需反复指称且有助于理解时才定义局部名称，并说明它是本文名称。有限检索不足以支持首次性声明。检索缺口及需要作者确认的定义放在正文外；不向每个定义附加检索说明。

## 组合名称、局部标签与对象承接

新命名或拼接已有名称时，必须核验组合的整体含义与用法。组成词各自通行，不证明组合也是公认方法名。缺少这一依据时展开关系，例如说明区间使用哪种方差估计，而不让紧凑标签代替定义；不据有限检索声称从未有人用过该名称。

区分惯用名称、描述性短语和本文局部标签。图表确需简称时，在首次使用处说明其对应对象及与正文名称的关系；已有合法连字符术语和有依据的新命名都可以保留。不要为省字或包装贡献给每个中间关系起名。

只统一同一对象的称呼。条件、由条件导出的表示及证明中的近似操作可以相关，但不是同义词；首次连接时说明推导关系，后文沿用准确名称或清楚的指代。使用 smooth、continuous、piecewise、random 等修饰词时核对具体对象及自变量，不能通过换名称转移性质。

重命名后核对正文、正式结果标题、图表和补充材料中指向同一对象的名称；保留标签、引用键和公式。不同对象不作全局同义替换；来源或定义没有变化时无需为普通重复使用重新检索。

## 保存格式

方向 `terms.json` 使用对象：`schema_version`、`topic_id`、`checked_at`、`terms`。每条术语包含：

- `concept_id`：稳定 ID。
- `preferred_term`、`aliases`：首选名称与真实同义名称。
- `definition_scope`：定义与有效范围。
- `distinguish_from`：不可混并的相邻概念。
- `sources`：公开 DOI 或文献 ID，附章节、页码或定义编号。
- `verified_at`：核验日期。

单稿私有定义、作者尚未发表的构造与专用记号留在项目中。共享术语表仅保存来自公开文献、可复用的概念。
