# 经典全文、方向规范与增量维护

## 语料与阅读门槛

四刊各以 2000 年至检索日正式发表的 25 篇经典论文为核心语料。阅读卡用于学习写作思路。现有 2000 年以前的十二篇历史范例不替代新核心库；其中符合年份的论文按 DOI 去重。

经典性结合长期引用、后续沿用和可核验的领域认可判断。保存筛选来源与日期，覆盖研究方向、年代、文章类型和作者群体。引用量帮助发现候选，不独立决定入选。近期代表作另建校准集，标明观察期与用途；本次初建为每刊额外两篇2020年以来论文，不占25篇经典核心数。以后按实际方向与期刊变化补充，不机械维持固定的近期数量。

先核验 DOI、题目、作者、正式年份、期刊和文章类型，再获取全文。优先出版社正式版，其次作者或机构公开稿、匹配的公开预印本。记录实际版本；未核对版本差异时不能把作者稿的章节安排宣称为最终排版要求。查找关联勘误和补记；经典文章也可能含已被纠正的过强措辞或历史归属，笔记与指南须采用修正后的判断。

下载后检查正文题目、作者、长度和末尾，拒绝封面、勘误、讨论回复、验证码和只有摘要的网页。扫描件进行 OCR；OCR 仅辅助阅读叙述，公式和专有名称回看原页。

只有实际阅读全文叙述并完成逐篇分析才标记 `status: read`。记录阅读范围；证明可以只分析组织和关键解释，但不得声称逐行验证证明。获取失败保留原候选、失败路径与替代选择理由，不悄悄用摘要补齐数量。

## 逐篇笔记

每篇保存以下原创分析，并标章节或 PDF 页码：

- 摘要选择了哪些信息，省略了哪些背景。
- 引言各段的任务，已有工作怎样自然引出贡献。
- 定义、直觉、方法、算法和理论的出现顺序与信息依赖。
- 定理前后哪些解释有必要，哪些条件通过引用承接。
- 模拟、应用和图表分别支持什么判断，结果如何回到开头问题。
- 讨论提供哪些新增认识；文章如何结束，或为何没有单独讨论。
- 可迁移的写作动作、特殊安排及不适用情形。

写作分析保持原创，不复制正文段落或保存全文到技能包。原 PDF、提取文本和下载日志放在技能之外的研究缓存。

核心 `core-corpus.json` 保存 `schema_version`、`journal_id`、`journal`、`checked_at`、`core_target`、`selection_policy`、`papers`。每篇含 `id`、`title`、`authors`、`year`、`doi`、`article_type`、`topics`、`selection_reason`、`citation_evidence`、`full_text`、`note`；`full_text` 记录公开 URL、版本、格式、源文件 SHA256、页数、实际阅读范围、日期与状态。笔记路径相对期刊目录。

只能通过网页工具完整阅读 PDF、无法取得原始字节时，`sha256` 留空，保存实际完整提取文本的 `extracted_text_sha256` 并标 `hash_scope: extracted_text` 和获取方式。来源原件与提取文本的散列不能混称；仅取得网页摘要或少量 PDF 片段不满足全文门槛。

近期校准记录放在同刊 `calibration-corpus.json`，逐篇字段与核心相同，使用独立ID和阅读卡，不重复核心DOI。指南明确哪些观察由经典支持、哪些由近期材料校准；不能把近期样本自动提升为test-of-time经典。

## 首次方向档案

稳定的方向 ID 对应研究问题与边界，维护关键词、同义名称和排除项。按“期刊 × 研究方向 × 文章类型”匹配，允许交叉标签。用户没有指定方向时从论文内容识别；无法可靠归类时不伪造专属档案。

新建方向前强制定向检索目标刊该方向，优先经典与最接近贡献的文章，补充近期校准。至少十篇目标刊、本方向、匹配文章类型的已读全文才能将档案标为完整；综述、讨论、原创方法等不同类型可供比较，但不混计十篇。以主要贡献和正式稿型判断，允许一篇有多个经核验类型标签，不能仅凭出现定理或真实数据归类。已有核心阅读卡直接复用，不重复下载和阅读同一版本。

在 `topics/<topic-id>/` 保存：

- `profile.md`：文章类型、写作规范、来源定位、适用条件和反例。
- `corpus.json`：方向定义、关键词、检索式、排除项、检索日期、`status`、`paper_ids`、目标 `article_type_id`、新增论文记录、规则更新记录。类型ID采用稳定分类，如 `original-methods`、`original-theory`、`computational-methods`、`applications-case-studies`、`discussion-paper`、`review` 或 `short-communication`。`type_evidence`按论文ID保存匹配的 `article_type_id`及 `basis`（对应原文或阅读卡位置和判据）。只把同类型、有依据的已读DOI计入十篇。
- `paper_ids` 可以引用该刊核心或近期校准论文；额外论文存同格式条目于 `additional_papers`，另含目标刊 `journal_id`，其 `note` 路径相对方向目录。按 DOI 去重，不能用同篇不同版本或不同 ID 凑数。跨类型补充材料另记 `supplementary_paper_ids`，不计门槛。
- `terms.json`：按 terminology-protocol 保存术语。

确实不足十篇时，记录检索范围和数量，将 `status` 设为 `provisional`。邻近方向或其他刊物可以作补充，但不计入十篇。继续用已核验材料完成稿件，不冒称方向建库完成。

## 形成规范

一篇论文支持的做法先作为观察。升级方向建议前，检查独立作者群体、适用情形及反例；升级期刊建议还需跨方向材料。每条经验规则标支持论文 ID 和位置。多个互不相同的结构可能都合适，保留条件化的选择依据。

官方要求、署名编辑建议、论文观察和个人偏好分别标记。官方现行格式由原始作者页和模板核验；经典文章只能提供论证观察。单稿的成功改法不自动成为所有稿件的通则。

## 后续调用

新的相关写作任务先加载档案，并执行轻量定向增量检索。按 DOI 或核验题录去重，只深读新增相关全文、既有规则的反例或冲突证据。同一轮连续逐段修改复用此次检索。

检索包括新发表文章及先前遗漏的旧经典，并核对影响来源可靠性的更正或撤回信息。记录此次检索日期、查询式、新增条目和受影响规则；没有可复用变化就不改档案、不产生例行提交。

方向边界、文章类型或官方要求变化时重审相关部分。只有足够的独立反证才重审整个方向，不凭一篇新文章判断期刊风格发生巨大变化。保留规则版本和替代关系以便回滚。

“进化”通过实际文件维护实现，不涉及模型训练，也不假设聊天记忆会永久保存。

## 校验和同步

运行 `scripts/check_resources.py`。初建百篇库完成时加 `--require-complete`；阅读缺口如实报告，不能以脚本通过替代实际阅读。

同步沿用已配置的发布工作副本和仓库，核对远端当前可见性，不自行更改。维护配置放在 Codex 用户目录的 `skill-maintenance/stat-journal-writing.json`，位于技能包之外，保存工作副本路径、目标仓库和自动同步开关；它记录当前安装者的选择，不向共享仓库传播个人路径或替其他用户授权。

`scripts/sync_resources.py` 读取该配置并默认预览；也可显式提供 `--worktree <path>`。`--apply --push` 才导出、提交与普通推送，须在当前任务或既有授权范围内使用。仅导出明确允许的技能资源，保留仓库独立 README。遇到脏工作区、远端新提交、冲突或认证失败时保存本地成果并报告，不强推。

社区安装者使用[社区贡献与安装更新](community-contributions.md)中的 `scripts/collaborate.py` 流程：本人明确开启，按具体方向和阅读卡准备差异，通过个人 fork 提交 PR，维护者审核合并。自动贡献不直接推送官方主分支；没有开启时继续本地积累。`scripts/update_installation.py` 提供独立安装更新入口，默认预览；保留本地修改，遇冲突停止。个人配置与授权不随安装包传播。
